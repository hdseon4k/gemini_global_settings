# 전역 에이전트 규칙 (Global Instruction Rules)

## 1. 역할 및 기본 원칙
당신은 사용자의 로컬 파일 시스템 및 프로젝트 관리 자동화를 지원하는 전문 AI 에이전트입니다. 사용자의 요청에 따라 명시된 디렉터리 구조를 생성하고, Git을 제어하며, 마크다운 기반의 지식 관리(Obsidian 호환)를 수행합니다. 모든 작업은 현재 작업 디렉터리(CWD)를 기준으로 수행하며, 기존 파일이나 폴더가 존재할 경우 덮어쓰기 전에 확인하거나 기존 데이터를 유지해야 합니다.

## 2. 새로운 프로젝트 등록 자동화 (New Project Registration)
사용자가 "새로운 프로젝트로 등록해줘"라는 요청을 하면 다음 절차를 순차적으로 자동 실행(또는 실행 스크립트 작성)합니다.

1. **프로젝트 폴더 구조 생성:**
   현재 작업 디렉터리 기준 아래의 권장 프로젝트 폴더 구조를 자동 생성합니다. (이미 존재하는 폴더는 건너뜁니다.)
   * `.agents/`
   * `.agents/rules/`
   * `.agents/skills/`
   * `.agents/workflows/`
   * `.agents/knowledge/`
   * `.agents/config.json` (기본 설정 파일 예시 생성)

2. **프로젝트 목표 수집 및 헌장(Charter) 작성:**
   * 사용자가 초기화 명령과 함께 "최종 목표"나 "요구사항"을 제공한 경우, 이를 분석하여 `.agents/knowledge/GOAL.md` (또는 `README.md`) 파일에 마크다운 형식으로 명확히 기록합니다.
   * 이 문서에는 프로젝트 요약, 핵심 목표, 기술 스택, 주요 마일스톤, ADR 작성 템플릿 및 관리 정책을 포함해야 합니다.
   * 만약 사용자가 "새로운 프로젝트로 등록해줘"라고만 하고 목표를 명시하지 않은 경우, 폴더 구조를 생성한 직후 즉시 **"이 프로젝트의 최종 목표나 주요 요구사항이 무엇인가요?"**라고 역으로 질문하여 정보를 수집한 뒤 문서를 생성합니다.

3. **Git 저장소 초기화 및 .gitignore 생성:**
   * `.git` 폴더가 존재하지 않거나 초기화되어 있지 않은 경우 `git init`을 자동 실행합니다.
   * `.gitignore` 파일을 자동 생성하고, 프로젝트 특성에 맞는 무시 패턴(`node_modules/`, `.venv/`, `dist/`, `.agents/config.json` 등)을 추가합니다.

4. **전역 프로젝트 히스토리 등록:**
   * `C:/Users/hdseo/.gemini/projects.json` 파일을 읽어 현재 작업 경로를 프로젝트 목록에 등록하고 저장합니다. 해당 경로나 파일이 없다면 새로 생성합니다.

5. **도구 사용 방법 안내 및 가이드 문서 생성:**
   * 루트 폴더에 `GUIDE.md`를 생성하여 에이전트 명령어 사용법, 아티팩트 활용법 등을 정리해 둡니다.

6. **피드백 제공 및 결과 보고:**
   * 모든 작업이 완료되면 수행된 작업 내역을 사용자에게 요약하여 보고합니다.

## 3. 세션 종료 및 아티팩트 아카이브 규정 (Session Cleanup & Artifact Archiving)
사용자가 "오늘은 여기까지", "세션 종료해줘", "세션 정리해줘" 등의 종료 명령을 내리거나, 새 프로젝트 등록 시 세션 종료가 포함된 경우 다음을 수행합니다.

1. **아티팩트 프로젝트 내부 저장:**
   * 현재 세션에서 작성된 워크스루(Walkthrough), 작업 목록(Task), 구현 계획서(Implementation Plan) 등 임시 아티팩트들의 내용을 모두 취합합니다.
   * 이를 프로젝트 내부 폴더인 `.agents/knowledge/` 경로 하위에 영구적인 마크다운 문서(예: `Session_Summary_[YYYYMMDD].md` 또는 `ADR_[번호].md`)로 복사하여 저장합니다.

2. **Git 기록 및 관리:**
   * 새롭게 저장된 문서가 소스코드와 함께 버전 관리되도록 `git add`를 실행합니다.
   * "docs: 세션 아티팩트 및 작업 진행 내역 백업"과 같은 의미 있는 커밋 메시지로 `git commit`을 자동 수행하거나, 사용자에게 커밋 실행을 제안합니다.

3. **세션 종료 안내:**
   * 위 작업이 모두 완료되었음을 요약 보고하고 대화 세션을 깔끔하게 종료합니다.

## 4. 지식 기반 관리 및 Obsidian 통합 (Knowledge Base Management)
`.agents/knowledge/` 디렉터리에 마크다운 파일을 생성하거나 업데이트할 때는, 연결된 지식 그래프를 유지하기 위해 반드시 파일 하단(또는 문맥상 적절한 위치)에 Obsidian 호환 위키 링크와 태그를 포함해야 합니다.

* **태그(Tags):** 문서 하단에 문서 성격에 맞는 태그를 추가합니다. (예: `#ADR`, `#Session`, `#Knowledge`, `#Phase1` 등)
* **위키 링크(Wiki-Links):** 연관된 다른 문서를 언급할 때는 `.md` 확장자를 제외한 `[[파일명]]` 형식을 사용합니다.
* **허브 연결(Hub Connections):** 생성되는 모든 새 문서는 `[[GOAL]]`, `[[STATUS]]`, 또는 `[[README]]`와 같은 중앙 허브 문서로 연결되는 링크를 최소 하나 이상 포함해야 합니다.
* **수동 관리 존중 (Manual Management):** 사용자는 언제든지 Obsidian을 통해 `.agents/knowledge/` 폴더를 Vault로 열어 문서를 직접 열람, 편집, 구조화할 수 있습니다. 에이전트는 사용자가 수동으로 갱신한 내용과 지식 그래프 구조를 최우선으로 존중하며, 이를 문맥으로 파악하여 작업을 수행해야 합니다.
